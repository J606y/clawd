# clawd 组件对接复核

用户追加要求：整合后检查各功能组件是否有更好的对接方式；重点把过去因不能修改 Hermes 核心而妥协的面板/sidecar/插件功能改为 clawd 原生实现，而非仅列建议或照搬旧补丁。当前开发仍在进行，本文件是复核范围，不代表已完成审查。

执行原则：逐项追溯补丁存在的原因与真实消费者。能够在本次核心集成范围内原生实现的，迁入明确的核心服务、事件或状态接口，并补行为测试、退役旧补偿逻辑；不能只包一层转发就称原生。涉及额外产品行为、协议替换或生产数据迁移的项目，单独说明边界，不擅自扩展。

## 复核边界

基于最终集成代码逐项给出：当前连接链路、可复现的问题或重复职责、建议接口、涉及消费者、兼容成本、验证方法。区分必须修复的契约缺陷、可纳入当前范围的小调整、需要另行确认的架构扩展。不得为了优化重设计面板、替换协议、删除功能或扩大生产变更。

## 检查项

1. 会话与运行状态：Web、TUI、API、子代理是否共用唯一运行事实；避免面板SQLite直写、影子状态和前端推测状态。
2. 事件与恢复：消息、工具、子代理、审批和续跑是否共享事件标识与顺序；断线补发、去重、重启恢复、取消与人工输入竞态是否闭合。
3. 配置、模型与技能：核心服务能否替代shell命令解析和文件绕读；保留配置校验、provider/model/effort锁定和profile隔离，不扩大密钥可见范围。
4. 文件与媒体：统一上传、产物、绝对路径映射和权限边界；保持absPath兼容、符号链接检查、下载鉴权与前端消费者一致。
5. 工具、MCP与实时浏览器：能力发现、任务身份、租约与控制权归属是否统一；服务缺失明确不可用，不能返回空内容伪装成功。
6. 后台任务：自动续跑归核心，检查cron、子代理和外部进程结果交付是否重复轮询/调度；既有审批和停止语义必须保留。
7. 生命周期：核心服务、面板静态资源、原sidecar能力的启动/停止、健康检查、版本协商、端口与错误传播是否完整，不留下孤儿进程。
8. 鉴权与测试：统一身份、CSRF/来源校验和请求错误模型；契约测试覆盖所有消费者，模拟单测与真实整合证据分开。
