# clawd 项目实施契约

用户已明确：按Claude Code项目模式，每项目必须有真实工作目录，普通聊天用普通模式。保留现有界面风格，不扩展多用户协作或远端数据迁移。

## 核心模型

复用 hermes_cli.projects_db 的项目实体和 primary_path，不另建独立项目身份。新增会话归属必须由核心统一存取，复用已有归属机制（若核验存在），否则在同一项目库新增有外键及唯一会话约束的关联表。所有读写使用显式 profile home，不能依赖浏览器选择。

项目必须有可解析、存在且可用的工作目录。可选择已有目录，也可在 clawd 工作区创建新目录；不得把生产Hermes home、密钥目录或系统目录当默认项目。不能把选目录当沙箱授权。归档不删目录、记忆或会话；此次不提供破坏性项目删除。普通会话无归属，只使用全局记忆。

运行中会话不允许改项目归属；空闲会话移动必须显式操作，保持 session_id。下一回合使用新归属，历史不重写；不能把另一项目历史自动提炼进新项目记忆。后台子代理/续跑按持久化父会话归属继承，不依赖新建默认会话。

## 记忆

全局记忆保留现有格式与行为。项目独立记忆由项目ID隔离，存入CLAWD_HOME/projects/<id>/memory/，不自动写入或提交用户代码仓库。工作目录里的项目规则继续使用已有AGENTS/CLAUDE发现机制。

项目会话启动时同时加载全局与本项目记忆，冻结已构建的提示前缀；本回合写入不偷偷改过去上下文。项目记忆读取、写入及审批必须绑定可信会话身份，客户端不能凭任意project_id越过会话归属。明确global/project作用域；默认project写入只用于项目会话，普通会话保持global；不得悄悄把项目记忆提升为global。复用现有容量、内容扫描、原子写入、锁与审批机制。

## API与消费者

核心提供 /api/projects 列表/创建、/api/projects/{id}读取/更新/归档、/api/projects/{id}/sessions归属列表、/api/sessions/{session_id}/project读取/显式绑定、/api/projects/{id}/memory读取及受控更新。实际请求/响应schema由实现代理写进 docs/clawd/project-api.md，冻结后再改面板消费者，不自造重复字段。

面板沿用现有分组布局，将文件夹入口改为项目；创建增加必需目录选择/创建信息；现有对话与项目聚合保持计数/分页/筛选一致。迁移旧文件夹仅提供显式迁移流程和回滚证据，未确定目录映射不修改生产数据。

API adapter现正由续跑代理修改；项目代理不改同文件，只提供可注册的 gateway/platforms/clawd_project_routes.py，由父代理整合挂载。项目服务和记忆归属链路不依赖面板HTTP代理。

## 验收

普通/项目两模式、目录必填/失效/重名/符号链接、同项目跨会话共享记忆、跨项目隔离、global/project写入、并发写入、审批拒绝、profile隔离、子代理/续跑归属、活动会话禁止迁移、归档非删除、重启后持久化、提示缓存不变。CLI/TUI与API真实初始化链路均需覆盖，不能只测孤立service。未接入运行时不得称功能完成。
